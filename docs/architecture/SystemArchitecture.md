# Документация архитектуры системы

## Введение
Данная документация описывает архитектуру системы, предназначенной для обработки документов. Система включает в себя несколько компонентов, каждый из которых выполняет свою уникальную функцию. Основные цели системы — обеспечить надежную аутентификацию пользователей, эффективную загрузку и обработку документов, а также интеграцию с машинным обучением для анализа данных.

## Архитектура системы
Система состоит из следующих основных компонентов:

### 1. Frontend

#### 1.1 Auth Service
- **Функции**:
  - Обеспечивает регистрацию пользователей, позволяя им создавать учетные записи.
  - Позволяет пользователям входить в систему и выходить из нее.
  - Управляет аутентификацией пользователей, проверяя их учетные данные и предоставляя доступ к другим сервисам.

- **Технологии**:
  - Использует **React** для создания интерактивного пользовательского интерфейса, что позволяет быстро обновлять данные на странице без перезагрузки.
  - Взаимодействует с бэкендом через **REST API**, что позволяет отправлять запросы на сервер для регистрации, входа и выхода пользователей.
  - Может использовать библиотеки для управления состоянием, такие как **Redux** или **Context API**, для хранения информации о пользователе и его сессии.

- **Обоснование**:
  - Использование React позволяет создавать отзывчивые и динамичные интерфейсы.
  - REST API обеспечивает четкое разделение между фронтендом и бэкендом, что упрощает разработку и поддержку системы. 
  - Аутентификация пользователей является критически важной для обеспечения безопасности и защиты данных, что делает Auth Service необходимым компонентом системы.

#### 1.2 Document Service
- **Функции**:
  - Позволяет пользователям загружать файлы для обработки, предоставляя удобный интерфейс для выбора и отправки документов.
  - Предоставляет возможность отслеживания статусов обработки загруженных документов, отображая пользователю актуальную информацию о состоянии его файлов.

- **Технологии**:
  - Реализован с использованием **React**, что позволяет создавать динамичные компоненты для загрузки файлов и отображения статусов.
  - Взаимодействует с бэкендом через **REST API**, что обеспечивает гибкость и возможность интеграции с различными клиентскими приложениями.
  - Может использовать компоненты для отображения статусов и загрузки файлов с помощью библиотек таких как **Material-UI** или **Ant Design**.

- **Обоснование**:
  - Document Service является ключевым компонентом для обеспечения функциональности загрузки и обработки документов, что является основной целью системы.
  - Использование React позволяет создавать интуитивно понятные интерфейсы, что улучшает взаимодействие пользователей с системой.
  - Возможность отслеживания статусов обработки документов пользователей о завершении обработки повышает уровень удовлетворенности пользователей и делает систему более эффективной.

Использование React для фронтенда позволяет создать интуитивно понятный и интерактивный интерфейс. Взаимодействие с бэкендом через REST API обеспечивает надежную и эффективную связь между компонентами системы.

### 2. Backend

#### 2.1 Auth Service
- **Функции**:
  - Управляет аутентификацией пользователей, проверяя их учетные данные (имя пользователя, пароль, email).
  - Обрабатывает регистрацию пользователей, включая валидацию уникальности имени пользователя и email.
  - Выдает JWT (JSON Web Token) для аутентификации пользователей при входе в систему.
  - Обеспечивает возможность выхода из системы и управления токенами.

- **Обоснование**:
  - Использование JWT обеспечивает безопасность и позволяет пользователям оставаться аутентифицированными без необходимости повторного ввода учетных данных.
  - Валидация email и уникальности имени пользователя предотвращает создание дубликатов и улучшает безопасность.

- **Технологии**:
  - Реализован с использованием Spring Boot, что обеспечивает простоту и гибкость в разработке.
  - Использует Spring Security для управления аутентификацией и шифрования паролей с помощью `PasswordEncoder`.
  - Включает в себя `EmailValidator` для проверки корректности введенных email-адресов.

#### 2.2 Document Service
- **Функции**:
  - Обрабатывает загрузку документов, их валидацию и отправку на проверку.
  - Управляет статусами документов, позволяя пользователям отслеживать состояние их файлов.
  - Обеспечивает асинхронную обработку загрузок, что позволяет системе эффективно управлять большими объемами данных.

- **Обоснование**:
  - Асинхронная обработка документов улучшает отзывчивость системы и пользовательский опыт, позволяя пользователям загружать несколько файлов одновременно.
  - Управление статусами документов позволяет пользователям получать актуальную информацию о состоянии их файлов.

- **Технологии**:
  - Реализован с использованием Spring Boot и аннотаций `@Async` для асинхронной обработки.
  - Использует `DocumentRepository` для взаимодействия с базой данных и хранения метаданных документов.
  - Включает в себя обработку файлов с использованием `MultipartFile` для загрузки документов.

#### 2.3 Message Broker (Kafka)
- **Функции**:
  - Обеспечивает асинхронное взаимодействие между компонентами системы, позволяя им обмениваться сообщениями без необходимости прямого взаимодействия.
  - Позволяет отправлять и получать сообщения о статусах документов и других событиях, что критично для высоконагруженных приложений.
  - Поддерживает обработку событий в реальном времени, что позволяет системе реагировать на изменения статусов документов мгновенно.

- **Обоснование**:
  - Использование Kafka позволяет масштабировать систему, добавляя новые экземпляры сервисов по мере необходимости, что особенно важно для приложений с высокой нагрузкой.
  - Kafka обеспечивает надежность и устойчивость к сбоям, позволяя системе продолжать работу даже в случае временных проблем с отдельными компонентами.
  - Асинхронная природа Kafka улучшает производительность, позволяя компонентам работать независимо друг от друга.

- **Технологии**:
  - Реализован с использованием Apache Kafka, который является популярным решением для обработки потоков данных.

#### 2.4 PostgreSQL DB
- **Функции**:
  - **Пользователи**:
    - Хранит информацию о пользователях, включая их учетные данные (имя пользователя, пароль, email).
    - Обеспечивает возможность выполнения операций CRUD (Create, Read, Update, Delete) для управления данными пользователей.

  - **Документы**:
    - Хранит метаданные загруженных документов, включая идентификаторы, статусы и другую информацию.
    - Поддерживает сложные запросы для управления данными документов, что позволяет эффективно отслеживать их состояние и выполнять операции над ними.

- **Обоснование**:
  - PostgreSQL обеспечивает надежное и безопасное хранение данных, что критично для защиты личной информации пользователей и документов.
  - Поддержка транзакций позволяет гарантировать целостность данных, что особенно важно при работе с учетными записями пользователей и документами.
  - Возможность использования сложных запросов и индексов улучшает производительность работы с данными.

- **Технологии**:
  - Использует PostgreSQL как реляционную базу данных, что обеспечивает высокую производительность и надежность.
  - Взаимодействие с базой данных осуществляется через Spring Data JPA, что упрощает работу с репозиториями и запросами.

#### 2.5 Object Storage
- **Функции**:
  - Хранит загруженные документы и обеспечивает доступ к файлам для дальнейшей обработки и скачивания.
  - Позволяет пользователям загружать и скачивать документы через API, обеспечивая удобный интерфейс для работы с файлами.

- **Обоснование**:
  - Использование облачного хранилища позволяет масштабировать систему и управлять большими объемами данных.
  - Облачное хранилище обеспечивает высокую доступность и надежность.

- **Технологии**:
  - Реализовано с использованием облачных решений, таких как Amazon S3.
  - Взаимодействие с объектным хранилищем осуществляется через API, что позволяет легко интегрировать его с другими компонентами системы.

Архитектура бэкенда спроектирована с учетом модульности, безопасности и производительности, что позволяет легко добавлять новые функции и компоненты, а также эффективно управлять данными пользователей и документами.

### 3. ML Server

#### 3.1 GOST Analysis
- **Функции**:
  - Определяет и классифицирует элементы документа (заголовки, абзацы, таблицы) в соответствии с требованиями ГОСТ.
  - Применяет правила форматирования (шрифты, размеры, отступы) для соответствия стандартам ГОСТ.

- **Обоснование**:
  - Автоматизация процесса классификации и форматирования документов значительно ускоряет работу и снижает вероятность ошибок, связанных с ручным форматированием.
  - Обеспечение соответствия стандартам ГОСТа повышает доверие пользователей к системе и улучшает качество предоставляемых услуг.

- **Технологии**:
  - Использует библиотеки обработки естественного языка (NLP), такие как `spaCy` или `NLTK`, для анализа текста и извлечения информации.

#### 3.2 Document Processing
- **Функции**:
  - Объединяет текстовые данные и форматирование, полученные от модели, в единый документ.
  - Сохраняет готовый документ в объектном хранилище для дальнейшего использования и доступа.
  - Отправляет уведомления через Message Broker (Kafka) о готовности документа.

- **Обоснование**:
  - Использование Python позволяет легко интегрировать библиотеки для работы с документами, что упрощает процесс сборки и сохранения.

- **Технологии**:
  - Использует библиотеки, такие как `python-docx` для работы с документами Word и `Pandas` для обработки данных.
  - Взаимодействует с REST API для получения данных и отправки результатов.



#### 3.3 Dataset Storage
- **Функции**:
  - Хранит данные для обучения моделей машинного обучения, включая тренировочные и тестовые наборы данных.
  - Обеспечивает доступ к данным для анализа и тестирования моделей, что позволяет улучшать их качество и точность.
  - Управляет версиями данных, что позволяет отслеживать изменения и восстанавливать предыдущие версии при необходимости.

- **Обоснование**:
  - Наличие отдельного хранилища для данных позволяет эффективно управлять процессом обучения и тестирования моделей, что критично для достижения высоких результатов.
  - Управление версиями данных помогает избежать проблем, связанных с несовместимостью данных и моделей.

- **Технологии**:
  - Использует облачные решения для хранения данных - Amazon S3.
  - Взаимодействует с системами управления данными, такими как Apache Airflow, для автоматизации процессов загрузки и обработки данных.

## Риски и ограничения

### 1. Риски

#### 1.1 Зависимость от команды
- **Описание**: Нехватка участников команды может привести к задержкам в выполнении задач и снижению качества работы.
- **Меры по снижению риска**: Регулярные встречи для оценки прогресса и перераспределения задач.

#### 1.2 Технические сложности
- **Описание**: Возможные проблемы с интеграцией различных компонентов системы (например, взаимодействие между фронтендом и бэкендом, бэкендом и ML).
- **Меры по снижению риска**: Проведение тестирования на ранних этапах разработки и использование прототипов для проверки взаимодействия.

#### 1.3 Ограниченные временные ресурсы
- **Описание**: Ограниченное время на выполнение проекта может повлиять на качество и полноту реализации.
- **Меры по снижению риска**: Приоритизация задач и фокус на ключевых функциях системы.

#### 1.4 Обучение модели
- **Описание**: Необходимость в обучении модели машинного обучения может потребовать значительных временных и вычислительных ресурсов.
- **Меры по снижению риска**: Оптимизация процесса обучения и использование относительно небольшого дата-сета на MVP.

### 2. Ограничения

#### 2.1 Временные ограничения
- **Описание**: Проект должен быть завершен в определенные сроки, что может ограничить возможности для тестирования и доработки.
- **Влияние**: Это может привести к снижению качества и функциональности системы.

#### 2.2 Ограниченные знания команды
- **Описание**: Некоторые члены команды могут не иметь достаточного опыта в определенных технологиях или методах.
- **Влияние**: Это может замедлить процесс разработки и привести к ошибкам.

## Обоснование выбора архитектуры

### 1. Модульность
Архитектура системы разделена на несколько модулей, каждый из которых отвечает за свою уникальную функцию. Это позволяет:
- **Упрощение разработки**: Команды могут работать над отдельными модулями параллельно, что ускоряет процесс разработки.
- **Легкость в поддержке**: Модули могут быть обновлены или заменены без необходимости изменения всей системы.

### 2. Использование REST API
Взаимодействие между фронтендом и бэкендом осуществляется через REST API, что обеспечивает:
- **Четкое разделение**: Фронтенд и бэкенд могут развиваться независимо друг от друга.
- **Гибкость**: Легкость в интеграции с другими сервисами и клиентскими приложениями.

### 3. Асинхронная обработка
Использование асинхронной обработки (например, через аннотацию `@Async` в Spring) в Document Service позволяет:
- **Улучшение отзывчивости**: Пользователи могут загружать несколько файлов одновременно, не дожидаясь завершения предыдущих операций.
- **Эффективное управление ресурсами**: Система может обрабатывать большие объемы данных без блокировки потоков.

### 4. Безопасность
Использование JWT (JSON Web Token) для аутентификации пользователей обеспечивает:
- **Безопасность**: Токены позволяют пользователям оставаться аутентифицированными без необходимости повторного ввода учетных данных.
- **Управление доступом**: Легкость в управлении правами доступа к различным компонентам системы.

### 5. Масштабируемость
Архитектура системы спроектирована с учетом масштабируемости:
- **Kafka как Message Broker**: Позволяет асинхронно отправлять и получать сообщения, что особенно важно для высоконагруженных приложений. Это также позволяет эффективно интегрировать ML-систему для обработки данных.
- **Облачные решения для хранения данных**: Использование Amazon S3 и PostgreSQL обеспечивает высокую доступность и надежность.

### 6. Интеграция с машинным обучением
Наличие ML-сервера для обработки документов и анализа данных позволяет:
- **Автоматизация процессов**: Снижение нагрузки на пользователей и минимизация человеческих ошибок.
- **Повышение точности**: Использование алгоритмов машинного обучения для анализа и обработки данных.
